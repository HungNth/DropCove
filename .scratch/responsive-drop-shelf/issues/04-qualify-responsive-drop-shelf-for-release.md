# 04: Qualify the responsive Drop Shelf for release

**Parent specification:** [Responsive Resizable Drop Shelf Specification](../spec.md)

**What to build:** Prove the complete responsive Drop Shelf in an installed self-contained Release build, fix any integration regressions, and leave one production-ready presentation whose geometry, popup, accessibility, lifecycle, and resource use satisfy the approved contract.

**Blocked by:** 03: Manage multi-item Shelf Batches in an anchored popup.

**Status:** needs-triage

**Testing seam:** Run the complete automated application/persistence suite once, then validate Windows-only behavior on the actual installed Release surface through UI Automation, direct pointer/keyboard interaction, real drag/drop, and the established performance measurement procedure.

**Demo path:** Exercise the final shelf end to end with normal content, multiple monitors or available DPI configurations, restart persistence, Edge Rail dismissal, shake/hotkey invocation, popup management, real Explorer drag-in/out, and the canonical 100-batch/1,000-item profile.

- [ ] The full automated suite passes with obsolete Compact/Expanded contracts removed and the approved state, persistence, geometry, lifecycle, and visual-request behaviors covered at their highest stable seams.
- [ ] The self-contained Release build completes with no errors or warnings introduced by this effort, and the installed application is the artifact used for runtime acceptance.
- [ ] Installed smoke proves all-edge/all-corner borderless resizing, hover affordance, minimum size, maximum work-area bounds, stable opposite-edge behavior, and no resize lag that interferes with drag interaction.
- [ ] Preferred size survives hide/show, Edge Rail dismissal, application restart, monitor changes, and temporary work-area clamping without confusing actual bounds with the durable logical preference.
- [ ] Removing the final Shelf Item from the visible Drop Shelf or Edge Rail always closes transient UI, transitions to `Hidden`, deletes preferred size, preserves Edge Rail placement, and makes the next opening `180 × 180`.
- [ ] Installed smoke proves exact responsive column boundaries, even card stretching, newest-first row order, vertical-only scrolling, stable bounds during mutations, and absence of Compact/Expanded controls or hidden mode transitions.
- [ ] Installed smoke proves the full popup placement, sizing, focus, `Esc`, outside-click, owner-lifecycle, item-action, and real item/batch drag contracts without changing shelf bounds.
- [ ] Current hotkey, shake, close-to-dismiss, tray, Edge Rail, fullscreen, drag-in/out, Pin/Unpin, Remove, Clear Temporary Items, persistence, Missing/Unavailable, same-integrity, reduced-motion, and accessibility behavior remains intact.
- [ ] Multi-monitor and DPI evidence records the actual configurations exercised. Unavailable configurations are not claimed; any required unverified configuration remains an explicit blocker.
- [ ] With 100 Shelf Batches and 1,000 Shelf Items, grid scrolling, popup opening/closing, pinning, removal, and drag initiation remain responsive with deferred item projections and lazy visual work.
- [ ] Installed Release `WorkingSet64` remains below `150 MB` while the shelf is visible and after dismissal, compared against the pre-change baselines of approximately `134.57 MB` and `141.05 MB`.
- [ ] Installed Release idle CPU remains at or below `0.1%`, shelf-show latency p95 remains at or below `150 ms`, and no continuous cursor polling or periodic resize work is introduced.
- [ ] Temporary profiles, seeded databases, test files, measurement artifacts not intended for retention, and installed smoke state are cleaned up; the user's original profile and persisted content are restored.
- [ ] The parent specification and ticket comments record exact automated, installed-smoke, configuration, and performance evidence without claiming scenarios that were not exercised.
