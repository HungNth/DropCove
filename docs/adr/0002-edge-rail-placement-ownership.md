# Separate Edge Rail preference from remembered placement

`settings.json` owns the user's `RailEdge` and explicit `RailMonitorId` preference, while `shelf.db` owns only the nullable monitor actually used for the latest non-empty Shelf dismissal. A fresh dismissal uses a connected explicit monitor first; otherwise it follows the pointer monitor, then falls back through the Drop Shelf monitor, the latest dismissal monitor, and the Windows primary display. A disconnected explicit monitor remains configured while the same pointer-first fallback keeps the Edge Rail reachable, and reconnecting it restores the explicit placement. Non-dismissal restoration reuses the current docked placement rather than resampling the pointer; Open Shelf uses the monitor where the Edge Rail is currently docked. This separates deliberate fixed placement, interaction-context placement, and restoration state without introducing competing owners.
