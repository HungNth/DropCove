# Let DropCove own normal Appearance Mode while Windows owns Contrast

Starting with `0.0.19`, `settings.json` owns one `AppearanceMode` value—`System`, `Dark`, or `Light`—and the Resident Instance resolves and synchronizes that choice across every WebView surface and native frame, including transactional preview through the existing Settings Save/Cancel lifecycle. This supersedes the prior decision that “Windows is the sole theme authority”: System still follows live Windows application-theme changes, while explicit Dark and Light remain fixed; Windows Contrast Theme always has higher rendering authority without changing the stored preference. The user control justifies process-wide appearance coordination and a strict settings-schema cutover, while preserving one semantic token source and avoiding per-surface themes, custom palettes, compatibility fields, or a second appearance store.
