# Materialize non-filesystem drops as app-owned Managed Files

DropCove keeps ordinary file and folder drops as external path references, but materializes accepted Unicode text and Website Image Virtual File bytes as app-owned Managed Files inside Profile Data. This preserves the existing filesystem-path and Windows Shell drag-out model without pretending that a URL, text payload, or stream-only image is already a Shelf Item. Ending a Managed File's Shelf Item lifecycle atomically records permanent cleanup and removes the reference; deletion is attempted immediately and retried durably if Windows still holds the file. External source objects are never deleted.

Managed Files and pending cleanup survive restart, update, and uninstall with the rest of Profile Data. On recoverable Shelf database failure, the managed storage joins the timestamped Recovery Backup defined by ADR-0003 so a clean active Shelf does not destroy content that the preserved database may reference. Website images use mandatory non-UI Windows Attachment Services, explicit HTTP(S) source evidence when available, Windows-policy-authoritative zone handling, and post-scan validation whose final supported bytes are authoritative. DropCove does not add HTTP URL fallback, generic virtual-file intake, security bypasses, content hashing, or shared backing files.

Managed intake uses an explicit durable `Staged` → `Ready` ownership transition rather than pretending SQLite and the filesystem share one transaction. `Staged` rows are never projected; same-volume promotion and startup reconciliation either finish the owned file or remove the unprojected item. Deletion authority comes only from `managed_files` or pending-deletion records, never from a path merely residing under Profile Data.
